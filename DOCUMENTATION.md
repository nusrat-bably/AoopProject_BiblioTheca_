# BiblioTheca Technical Documentation

**Version:** 3.0.0  
**Last updated:** September 22, 2026

## 1. Overview

BiblioTheca combines a library catalogue with authentication, persistent player progress, dungeon games, and an AI librarian. The browser application is backed by a Spring Boot REST service. PostgreSQL on Supabase is the supported persistent database.

## 3. Repository Layout

- `client/` - Vite React application, routes, games, context, and browser persistence.
- `springboot/demo/` - Spring Boot application, REST controllers, JPA entities, repositories, services, and seed data.
- `springboot/demo/src/main/resources/application.properties` - runtime configuration.
- `springboot/demo/src/main/java/com/bibliotheca/model/` - `Book` and `Player` entities.
- `springboot/demo/src/main/java/com/bibliotheca/repository/` - JPA repositories.
- `server/` - unused legacy Mongoose files; not connected to the current application.

## 4. Runtime Data Flow

The client reads `VITE_API_URL` and calls the Spring API. Spring Data JPA maps API operations to Supabase PostgreSQL. On startup, `DataInitializer` checks `books`; it inserts starter books only when that table is empty. Player updates and unlocked books are saved through `PlayerRepository` and `PlayerService`.

```text
Browser -> VITE_API_URL -> Spring controllers -> JPA repositories -> Supabase PostgreSQL
                                  |
                                  +-> Gemini API (chat only)
```

## 5. Supabase Configuration

Set these backend environment variables from the Supabase **Connect** dialog. Use a JDBC URL, not the browser Supabase URL or anon key:

```properties
SPRING_DATASOURCE_URL=jdbc:postgresql://<host>:5432/postgres?sslmode=require
SPRING_DATASOURCE_USERNAME=postgres.<project-ref>
SPRING_DATASOURCE_PASSWORD=<database-password>
GEMINI_API_KEY=<gemini-key>
```

The application maps them in `application.properties`:

```properties
spring.datasource.url=${SPRING_DATASOURCE_URL}
spring.datasource.driverClassName=org.postgresql.Driver
spring.datasource.username=${SPRING_DATASOURCE_USERNAME}
spring.datasource.password=${SPRING_DATASOURCE_PASSWORD}
spring.jpa.hibernate.ddl-auto=update
spring.jpa.database-platform=org.hibernate.dialect.PostgreSQLDialect
```

Set the frontend environment separately:

```bash
VITE_API_URL=https://<deployed-backend-domain>
```

Never commit database passwords, API keys, or Supabase service-role keys. The repository documentation previously contained H2 and MySQL instructions and an exposed Gemini example key; those instructions have been removed.

## 6. Database Schema

Hibernate creates or updates these tables in Supabase.

### `books`

| Column | Type | Notes |
| --- | --- | --- |
| `id` | bigint | identity primary key |
| `title` | varchar | book title |
| `author` | varchar | author |
| `category` | varchar | category |
| `isbn` | varchar | ISBN |
| `description` | varchar(5000) | description |
| `is_corrupted` | boolean | dungeon state |

### `players`

| Column | Type | Notes |
| --- | --- | --- |
| `id` | bigint | identity primary key |
| `username` | varchar | display name |
| `email` | varchar | unique login email |
| `password` | varchar | currently legacy plain-text storage |
| `knowledge_points` | integer | game economy, defaults to 100 |
| `last_regeneration_time` | timestamp | lockout tracking |
| `last_daily_reward_claimed` | timestamp | reward cooldown |

### `player_unlocked_books`

Join table generated by `@ElementCollection`, with `player_id` and `book_id` columns. Each player can unlock multiple books.

## 7. API Surface

| Method | Route | Purpose |
| --- | --- | --- |
| GET | `/api/books` | list books |
| POST | `/api/players/register` | register player |
| POST | `/api/players/login` | log in by username or email |
| GET | `/api/players/{id}` | read player state |
| POST | `/api/players/{id}/kp` | update knowledge points |
| POST | `/api/players/{id}/unlock-book` | save a book unlock |
| POST | `/api/players/{id}/complete-level` | save level result |
| GET/POST | `/api/players/{id}/daily-reward/status|claim` | daily rewards |
| POST | `/api/chat` | proxy a Gemini request |

## 8. Local Development

```bash
cd client
npm install
npm run dev
```

In another terminal:

```bash
cd springboot/demo
./mvnw spring-boot:run
```

The default local API is `http://localhost:8080`. The backend binds to `${PORT:8080}` for Railway-style hosting.

## 9. Checks

```bash
cd client && npm run build
cd ../springboot/demo && ./mvnw test
```

The frontend build does not require a live database. Backend startup and the context test require valid PostgreSQL environment variables and a reachable database.
